# Проверка TgCalls-rs на iPhone

| Проверка | Статус |
| --- | --- |
| XCFramework, arm64 iPhone и оба среза симулятора | [Пройдено в CI](https://github.com/omauser119/tgcalls-rs/actions/runs/44319151754) |
| Ограничения памяти, fuel, импорты, завершение гостя | Пройдены автоматизированные тесты Wasmi на Linux |
| H.264, подпись кадра, повреждение и повтор пакета | [Пройден локальный PyTGCalls-тест](../pytgcalls-h264-e2e/README.md) |
| Установка IPA, маршрутизация аудио, реальный вызов на iPhone | Ожидает подписанной сборки и устройства |
| Метрики CPU, RSS, latency и качество звука на iPhone | Не замерены |

На одном устройстве соберите серию с одинаковой версией iOS, одинаковой
сетью и фиксированным тестовым PCM. В debug-меню переключайте **Calls
Harden Mode** перед новым звонком. Проверьте сохранение значения после
перезапуска. Используйте официальный клиент на другом устройстве для
личных звонков в обе стороны, группового аудио, видео, ReplayKit и
конференции с верификацией E2E. Для simulcast включайте одновременно
получателей с разными ограничениями высоты и проверяйте входящие SSRC.

На установленном звонке переключите Wi‑Fi на LTE и обратно, смените
аудиомаршруты, примите прерывание Siri или CallKit и переведите приложение
в background. Запишите время восстановления и пропуски аудио. В отдельной
подписанной тестовой сборке прогоните исчерпание fuel и ошибочный буфер
гостя. Хост должен сохранить работоспособность, а диагностика должна
показать остановку повреждённого экземпляра Wasmi.

Соберите CPU и RSS через Instruments на каждом режиме, сквозную задержку
через записанную в тестовый тракт метку, качество речи по одному и тому же
источнику и одинаковым условиям потерь. Сохраните версию обоих клиентов и
сырые данные для каждой попытки. Linux-замеры не покрывают эти сценарии.
