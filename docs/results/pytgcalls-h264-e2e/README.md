# PyTGCalls, H.264 и шифрование кадров

18 ноября 2026, Linux x86-64, Intel Core i5-3230M, PyTGCalls 3.0.1. Стенд
вызывает `PyTgCalls.send_frame` и отправляет синтетические I420-кадры 160×96
через реальный Rust-бэкенд. Два локальных воркера согласуют ICE/DTLS/SRTP,
передают пакеты через очередь хоста и декодируют H.264 через `rusty_h264`.
В строках с E2E оба участника используют `tde2e` из TDLib на ревизии
`e894536b2f46caad93f997448d2daff9431b19dd`. Стенд создаёт и подтверждает
локальный блок вступления для двух синтетических участников.
[Спецификация E2E Telegram](https://core.telegram.org/api/end-to-end/group-calls)

По три новых процесса на вариант, пять кадров разогрева и 60 измеряемых
кадров на процесс. Кадры подаются без ожидания между ними. Задержка измерена
от передачи I420 в бэкенд до получения декодированного I420. CPU включает
PyTGCalls, оба Rust-воркера и шифрование кадров. RSS — пиковая память всего
процесса по `VmHWM`. В таблице указаны медианы отдельных прогонов.

| Вариант | Доставлено | Кадр/с | p95 кадра, мс | CPU, с на 60 кадров | Пиковая RSS, МиБ |
| --- | ---: | ---: | ---: | ---: | ---: |
| Native H.264 | 180/180 | 225,30 | 4,80 | 0,265 | 94,0 |
| Native H.264 + E2E | 180/180 | 178,69 | 6,38 | 0,334 | 97,0 |
| Wasmi H.264 | 180/180 | 6,44 | 168,31 | 9,290 | 157,8 |
| Wasmi H.264 + E2E | 180/180 | 6,21 | 178,32 | 9,616 | 160,1 |

Все шесть прогонов с E2E подтвердили подлинность 60 кадров и отклонили
изменённый кадр и повтор корректного кадра. Wasmi в этой конфигурации
обрабатывает менее семи кадров в секунду даже при 160×96. Требование
производительности для видео в Harden Mode пока не подтверждено. Результаты
относятся к локальному тракту с тестовым MTProto-контроллером. Совместимость
с конференцией Telegram, сетевые задержки и производительность на iPhone
требуют отдельных прогонов на устройстве. [Сырые результаты](runs.json)

## Воспроизведение

```sh
cargo build --locked --release -p tgcalls-ffi
bash scripts/build-wasm.sh
cmake -S benchmarks/tde2e-provider -B /tmp/tgcalls-bench-crypto \
  -DCMAKE_BUILD_TYPE=Release -DTD_SOURCE_DIR=/path/to/pinned/td
cmake --build /tmp/tgcalls-bench-crypto --target tgcalls_bench_crypto
python benchmarks/pytgcalls_h264_e2e.py \
  --library target/release/libtgcalls_ffi.so \
  --crypto /tmp/tgcalls-bench-crypto/libtgcalls_bench_crypto.so \
  --frames 60 --warmup 5
```

Для Wasmi добавьте `--wasm artifacts/tgcalls-worker.wasm`. Вариант без
шифрования кадров запускается без `--crypto`; SRTP остаётся включённым.
