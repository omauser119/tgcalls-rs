# Замеры после оптимизации Linux-аудиотракта

[Новые замеры с равным объёмом PCM и исправленным ICE](pcm-ice/README.md)

Историческая серия ниже использовала 20 мс на внешний вызов NTgCalls. Его
аудиовход 3.0.7 обрабатывает первые 10 мс, поэтому старые междвижковые цифры
CPU получены на разном объёме аудио. [Реализация аудиовхода NTgCalls](https://github.com/pytgcalls/ntgcalls/blob/v3.0.7/ntgcalls/src/media/audio_streamer.cpp)

В Harden Mode таймеры опроса PCM в обоих направлениях заменены уведомлениями
`eventfd`. Кодер за один проход переводит PCM в формат Opus и вычисляет RTP
audio level. Выпуск декодированного кадра планируется по сроку jitter buffer
и длительности кадра. Параметры Opus и границы seccomp в сравнении одинаковы.

## Локальный WebRTC loopback

Один чистый ICE/DTLS/SRTP-звонок, стерео PCM 48 кГц с кадрами по 20 мс,
0,5 с разогрева и 4 с измерения. По три свежих процесса для каждой версии
и режима, с чередованием порядка версий. Каждый прогон доставил все 200
измеряемых кадров. В таблице медианы трёх прогонов. Медиана p95 рассчитана
из p95 отдельных прогонов.

| Метрика | Обычный до | Обычный после | Harden Mode до | Harden Mode после |
| --- | ---: | ---: | ---: | ---: |
| Медиана аудио RTT, мс | 45,72 | 42,71 | 45,03 | 44,63 |
| p95 аудио RTT, мс | 47,01 | 43,87 | 46,16 | 45,38 |
| CPU процесса и helper, с | 1,00 | 0,98 | 0,97 | 1,07 |
| Пиковая сумма RSS, МиБ | 34,66 | 37,64 | 40,34 | 44,04 |
| Добровольные переключения контекста helper | — | — | 4 415 | 645 |

На одинаковой нагрузке число добровольных переключений helper снизилось на
85,4%. p95 обычного режима снизился во всех трёх парных прогонах. Изменение
CPU обычного режима мало. В Harden Mode CPU вырос, пиковая RSS выросла в
обоих режимах. Сырые строки сохраняют число PLC-кадров во время хвоста
приёма после остановки отправителя. Эти кадры не входят в RTT или счётчик
доставленных кадров. [Сырые результаты](linux-loopback.json)

## Групповой аудиозвонок Telegram

Обычная закрытая группа с одним участником. По три свежих звонка и процесса
на режим, 6 с синтезированного PCM на каждый успешный прогон. NTgCalls 3.0.7
использован как реализация для сравнения на C++ WebRTC. Метрики в таблице —
медианы успешных прогонов, с отдельным учётом отказов.

| Реализация | Подключения | Вход, мс | ICE/DTLS после ответа, мс | CPU, с | Пиковая RSS, МиБ |
| --- | ---: | ---: | ---: | ---: | ---: |
| Rust | 1/3 | 1 186 | 669 | 0,74 | 83,18 |
| Rust Harden Mode | 2/3 | 1 021 | 643 | 0,80 | 88,93 |
| NTgCalls 3.0.7 | 3/3 | 1 147 | 678 | 0,66 | 91,18 |

Проверка сохранила все три таймаута Rust. Во всех успешных прогонах Telegram
подтвердил источник. Успешным запускам Rust потребовалось меньше RSS. CPU и
надёжность подключения в этой серии лучше у NTgCalls. Условия с одним
участником измеряют отправку аудио и время подключения. Сквозная задержка,
дефекты декодирования на другом устройстве и общий уровень безопасности по
этой серии не определяются. [Сырые результаты](telegram-solo.json)
